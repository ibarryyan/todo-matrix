## 1. 需求背景

所有待办平铺在一天里，工作、生活、写作混在一起：既看不出「今天工作推进了多少」，
也很难只盯着一个模块做事。本任务给任务加一层**模块**维度：

- 顶部一排模块标签（全部 / 工作 / 生活 / 写作 / 其他 / ＋），一次只看一个模块；
- 模块可增删（预设三家 + 自定义，上限 8 个）；
- 删除模块时其任务归入内置模块「其他」，不丢数据。

**不做的事**：不做模块的排序 / 颜色 / 图标、不做跨模块统计对比、不做模块维度的点阵图。

## 2. 功能范围

### 2.1 包含

| # | 功能 | 说明 |
|---|---|---|
| F1 | **模块标签栏** | 「全部 / 各模块 / 其他 / ＋」，标签上显示**当天**该模块的 `完成/总数` |
| F2 | **按模块筛选** | 选中模块后只显示该模块任务，空态文案带上模块名 |
| F3 | **归属选择** | 输入区第二行是原生 `<select>`，决定新任务归入哪个模块；切到具体模块时自动同步 |
| F4 | **新增模块** | `prompt` 输入名称，≤6 字、不重名、上限 8 个，新增后自动切到该模块 |
| F5 | **删除模块** | 仅自定义模块，且只在停在该模块时出现删除键；先统计 → 二次确认 → 确认后才改数据 |
| F6 | **任务不丢** | 删除模块后，其下所有任务（含历史日期）的 `mod` 改为 `other` |
| F7 | **「其他」兜底** | 内置模块，不可删；无 `mod` 或 `mod` 指向已删除模块的任务一律归入此处 |
| F8 | **老数据兼容** | 无 `modules` 的存档回落预设三家；无 `mod` 的任务归入「其他」 |
| F9 | **清除已完成按视图** | 在具体模块下只清该模块；「全部」视图下行为与过去一致 |

### 2.2 不包含（明确排除）

- ❌ 模块排序 / 拖拽 / 改名 / 颜色 / 图标
- ❌ 模块维度的计分条与点阵图（**统计口径保持全局不变**）
- ❌ 跨模块移动任务、批量改归属
- ❌ 模块与日期的组合视图（如「本周工作」）

## 3. 非功能约束

| 类别 | 约束 |

| **代码风格** | 2 空格缩进、分号结尾、`const` 优先；最小实现 |

## 4. 数据格式变更

```json
{
  "version": 1,
  "modules": [ { "id": "work", "name": "工作" }, { "id": "life", "name": "生活" } ],
  "days": { "2026-11-03": { "tasks": [
    { "id": "tm9x2ka1b", "text": "写周报", "mod": "work", "link": "https://example.com", "done": false, "at": 1761475200000 }
  ] } }
}
```

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `modules` | `array` | ❌ 可选 | `[{id, name}]`；缺失 / 空数组时回落预设三家（工作 / 生活 / 写作）并写回 `state` |
| `task.mod` | `string` | ❌ 可选 | 必须是当前 `modules` 中存在的 id；否则（缺失 / 模块已删除）在读取时归入 `other` |
| `other` | — | — | 内置模块 id，**不在** `modules` 数组里，不可删除，始终排在标签栏最后 |

> **已知边界**：`modules` 目前不在 TASK-001 的导入校验字段表内。若导入的备份不含 `modules`，
> 加载时会回落预设三家，任务按 `mod` 是否匹配归入对应模块或「其他」。待 TASK-001 实现时一并补齐。

### 实现说明

- **模块是全局配置，不是按天数据**：`state.modules` 存在顶层，`task.mod` 只存 id。
  这样「工作」在每一天都是同一个模块，删模块时能一次性把所有日期的任务迁到「其他」。
- **`other` 不在 `modules` 数组里**：它是兜底容器，`modList()` 在渲染时把它拼在最后。
  好处是删除模块永远有去处，且它天然不可删（不在可删判定范围内）。
- **`modOf(task)` 是唯一的归属判定入口**：`mod` 缺失或指向已删模块都返回 `other`。
  筛选、计数、小签三处都走它，避免出现「有任务但哪个模块都看不见」的黑洞。
- **删除模块分两步**：先遍历统计条数 → `confirm` → 确认后才改 `mod` 并 `splice`。
  用户在确认框点「取消」时，一个字节都不动（沿用 AGENTS.md 的失败路径不改数据原则）。
- **统计口径刻意不动**：`renderTicker` / `renderMatrix` 仍用 `countOf` / `doneOf` 全量统计，
  模块只影响 `visibleTasks()`。这样点阵图的既有语义（直径=当天任务量、墨色=当天完成度）完全不变。
- **「清除已完成」跟随视图**：这是唯一被调整的业务动作——在具体模块下只清该模块，
  在「全部」下与过去完全一致。播报文案带上模块名，避免误以为清了全部。
- **`wipeBtn` 保留 `modules`**：清空的是「记录」不是「配置」，模块名属于后者。
