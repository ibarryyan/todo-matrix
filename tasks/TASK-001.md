## 1. 需求背景

当前应用的所有数据只存在于**单个浏览器的 `localStorage`** 中（键 `dotledger.v1`），存在两个真实风险：

1. **不可迁移**：换设备、换浏览器、重装系统时，历史记录无法带走。
2. **不可恢复**：浏览器清除站点数据、`localStorage` 配额超限或隐私模式下，记录会静默丢失
   （`save()` 失败时仅 `announce()` 提示，且不回滚内存状态，见架构文档 6.3）。

**远程 README 已确认这一痛点** —— 2026-11-01 同步的对外发布版 `README.md` 中：

- L146「❌ 换浏览器 / 清缓存，数据不跟随」
- L148–155「手动备份，在浏览器控制台执行 `copy(localStorage.getItem('dotledger.v1'))`」
- L164「没有数据导出按钮（见上文的控制台方案）」

也就是说，目前**唯一**的备份方式是让用户打开开发者工具手工跑 localStorage 命令 —— 对普通用户等于没有备份。
本任务即用两个按钮把它变成人人可用的功能。实现后需同步修订上述三处文案。

用户需要一个**零依赖、纯前端**的备份与恢复手段。本任务即提供「导出全部数据为 JSON 文件」+
「从 JSON 文件整体恢复数据」两个动作。

**不做的事**：不做云同步、不做自动备份、不做增量/合并导入、不做数据格式升级迁移。

## 2. 功能范围

### 2.1 包含

| # | 功能 | 说明 |
|---|---|---|
| F1 | **导出备份** | 点击后把当前 `state` 序列化为 JSON 文件并触发浏览器下载 |
| F2 | **导入备份** | 通过文件选择器选择一个 `.json` 文件 |
| F3 | **导入前严格校验** | 校验不通过则拒绝导入并提示原因（见第 5 节） |
| F4 | **导入前用户确认** | 校验通过后弹确认框，说明「将被整体替换，不可撤销」 |
| F5 | **写入优先** | 先写 `localStorage` 成功，再更新内存 `state` 并重渲染 |
| F6 | **失败不破坏原数据** | 校验失败 / 用户取消 / 写入失败，均保持原状 |
| F7 | **无操作反馈** | 成功与失败都通过 `announce()` 播报 |

### 2.2 不包含（明确排除）

- ❌ 数据合并 / 增量导入 / 按日期选择导入
- ❌ 自动定时备份、云端同步、账号体系
- ❌ 导入数据的版本升级或字段迁移
- ❌ 文件格式选择（仅 JSON，不做 CSV / Markdown）
- ❌ 撤销导入（由「导入前确认」承担）
- ❌ 修改主题相关的任何逻辑
- ❌ 重构现有渲染 / 状态模块

## 4. 数据格式

### 1.1 契约修订（2026-11-04）

本契约写于 TASK-002（待办附链接）与 TASK-003（任务分模块）之前，数据结构已扩充。实现时按**当前代码**
把三个后增字段纳入校验与导出范围，否则备份会丢模块、也会漏掉链接：

- `state.modules` —— 模块配置（`[{id, name}]`，缺省时导出补预设三家）
- `task.mod` —— 任务归属模块 id
- `task.link` —— 任务附带的 http(s) 链接

### 4.1 顶层结构（与 `main.js` 内存 `state` 完全一致）

```json
{
  "version": 1,
  "modules": [
    { "id": "work",  "name": "工作" },
    { "id": "life",  "name": "生活" },
    { "id": "write", "name": "写作" }
  ],
  "days": {
    "2026-10-27": {
      "tasks": [
        { "id": "tm9x2ka1b", "text": "整理会议纪要", "mod": "work", "done": false, "at": 1761475200000 },
        { "id": "tm9x2kc7f", "text": "修复 WebSocket 断连", "mod": "work", "link": "https://example.com/issue/42", "done": true, "at": 1761475231000 }
      ]
    },
    "2026-11-03": {
      "tasks": [
        { "id": "tm9y1qq0z", "text": "预排下周评审", "mod": "life", "done": false, "at": 1762080000000 }
      ]
    }
  }
}
```

### 4.2 字段规格

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `version` | `number` | ✅ | 必须严格等于 `1`（当前唯一受支持版本） |
| `modules` | `array` | ⭕ | **可选**（老备份没有该字段）。出现时必须是非空数组、≤8 项；`id` 非空且唯一、不占用保留字 `all` / `other`；`name` 去空格后非空、≤6 字、互不重复、不叫「其他」 |
| `days` | `object` | ✅ | 普通对象；**不得为 `null`、数组或其他类型** |
| `days` 的键 | `string` | ✅ | 必须匹配 `^\d{4}-\d{2}-\d{2}$`，且为**真实存在的日期**（回环校验 `keyOf(parseKey(k)) === k`，用于排除 `2026-02-30`、`2026-13-01` 等） |
| `days[v]` | `object` | ✅ | 普通对象，当前只识别 `tasks` 一个键 |
| `tasks` | `array` | ✅ | 必须是数组；**不允许空数组**（项目既有约定：当天无任务即删除该日期键） |
| `tasks[i]` | `object` | ✅ | 普通对象，不得为 `null` 或数组 |
| `task.id` | `string` | ✅ | 非空；**在整份文件内全局唯一** |
| `task.text` | `string` | ✅ | `trim()` 后非空；长度 ≤ 120（与 `index.html` 的 `maxlength="120"` 一致） |
| `task.done` | `boolean` | ✅ | 必须是 `true` / `false`，不接受 `"true"` / `1` / `0` 等 |
| `task.at` | `number` | ✅ | 必须是有限数字（`Number.isFinite`），毫秒时间戳 |
| `task.mod` | `string` | ⭕ | 可选；出现时必须是非空字符串。缺省或指向已删模块时按「其他」处理 |
| `task.link` | `string` | ⭕ | 可选；出现时必须是非空字符串且 ≤500 字符。协议合法性在归一化阶段用 `safeLink()` 复检，**不合法只丢链接、保留任务** |

### 4.3 导出文件

- 内容：`JSON.stringify(state, null, 2)`，`state` 原样输出，**不添加任何包装字段**
  （如 `exportedAt` / `app` / `meta` 等，以保证导入端结构与内存一致）。
- 文件名建议：`dotledger-backup-YYYY-MM-DD.json`（`YYYY-MM-DD` 为导出当天）。

### 4.4 范围要求

- **必须导出全部数据**：`state.days` 中的**所有**日期 —— 含历史日期与未来日期
  （未来日期用于「预先安排」），不得按点阵图的 18 周窗口裁剪。

## 5. 导入校验规则

校验必须**全部通过**才进入确认环节；任一项失败即整体拒绝（fail-fast）。

| 级别 | 检查项 | 失败提示要点 |
|---|---|---|
| R1 | 文件已选择且字节数 > 0 | 未选择文件 |
| R2 | `JSON.parse` 成功 | 文件不是合法 JSON |
| R3 | 根节点是普通对象（非 `null`、非数组） | 根节点必须是对象 |
| R4 | `version` 存在且 `=== 1` | 数据版本不受支持（当前支持 1） |
| R5 | `days` 存在且是普通对象（非 `null`、非数组） | `days` 必须是对象 |
| R6 | 每个 `days` 的键匹配 `^\d{4}-\d{2}-\d{2}$` | 日期键格式错误 |
| R7 | 每个日期键是真实日期（回环校验） | 日期不存在 |
| R8 | 每个 `days[v]` 是普通对象且 `tasks` 是数组 | 某天的数据结构非法 |
| R9 | `tasks` 非空 | 存在无任务日期 |
| R10 | 每个 `task` 是普通对象，`id` 为非空字符串且全局唯一 | 任务 id 非法或重复 |
| R11 | 每个 `task.text` 是字符串，`trim()` 后非空且长度 ≤ 120 | 任务文本为空或超长 |
| R12 | 每个 `task.done` 是 `boolean` | 完成状态字段类型非法 |
| R13 | 每个 `task.at` 是有限数字 | 时间戳字段非法 |
| R14 | `modules` 若出现：是非空数组、≤ `MOD_MAX` 项 | 模块数量非法 |
| R15 | 每个模块是普通对象，`id` 非空字符串且全局唯一，不占用保留字 `all` / `other`，`name` 非空、≤6 字、互不重复、不叫「其他」 | 模块 id / 名称非法或重复 |
| R16 | 每个 `task.mod` 若出现必须是非空字符串 | 模块归属字段非法 |
| R17 | 每个 `task.link` 若出现必须是非空字符串且 ≤500 字符 | 链接字段非法 |

**补齐现有 `load()` 的缺口**：R5 必须显式排除 `null`（因为 `typeof null === 'object'`），
R6–R17 是 `load()` 完全没有的字段级校验，导入时**必须全部实现**。

**归一化（已实现）**：校验通过后构造只含 `{ version, modules, days }` 的新对象再写入，未知字段丢弃，
任务只保留 `{id, text, mod, done, at, link?}`。`mod` 缺省补 `other`；`link` 经 `safeLink()` 复检，
`javascript:` / `ftp:` 等非法协议**只丢链接、保留任务**（与手工录入的行为一致）。

## 6. 异常处理

| 场景 | 处理方式 | 数据影响 |
|---|---|---|
| 未选择文件 / 选择后取消文件框 | 静默返回或 `announce('已取消')` | 无 |
| 文件为空（0 字节） | `announce` 提示，拒绝导入 | 无 |
| JSON 解析失败 | `try...catch` → `announce('文件不是合法 JSON，导入已取消')` | 无 |
| 结构 / 字段校验失败 | `announce` 具体原因，拒绝导入 | **无** |
| 文件读取失败（`FileReader` onerror / abort） | `announce` 提示 | **无** |
| 用户在确认框选择「取消」 | `announce('已取消导入')`，不写盘 | **无** |
| `localStorage.setItem` 抛异常（配额满 / 隐私模式） | `announce('本地存储写入失败，原有数据保持不变')`；**不更新内存 `state`** | **无** |
| 导入成功 | `announce('已导入 X 天、Y 条记录')`；写盘 → 更新内存 → `selected` 重置为今天 → 四个渲染 | 整体替换 |

**硬性要求（来自需求第 6、7 条）**：
- 写入 `localStorage` **成功之后**才更新内存 `state`。
- 任何失败路径都**不得修改** `state`，也不得调用 `save()`。
- 建议实现顺序：`校验 → confirm → 写盘（try） → 成功后赋 state → 重渲染`。

## 8. 验收标准

1. ✅ 点击「导出备份」后浏览器下载一个 `.json` 文件，文件名含日期。
2. ✅ 导出文件内容为合法 JSON，且 `version === 1`、`days` 对象结构完整。
3. ✅ 导出数据**包含所有历史日期与未来日期**，不因 18 周窗口被裁剪。
4. ✅ 导出的文件可被本功能重新导入，导入后数据与导出前**完全一致**（往返无损）。
5. ✅ 点击「导入备份」弹出系统文件选择器，且仅接受 `.json`。
6. ✅ 导入合法文件前必须弹出确认框，明确提示「当前数据将被整体替换」。
7. ✅ 确认后：先写 `localStorage`，成功后才更新内存状态并刷新报头 / 清单 / 计分条 / 点阵图。
8. ✅ 校验失败、用户取消、写入失败三种情况下，**原有数据完全不变**，且有明确提示。
9. ✅ 整个流程**不读取、不写入、不改变** `dotledger.theme`，主题保持不变。
10. ✅ 未引入任何新依赖（无 npm、无 CDN、无第三方库）。
11. ✅ 新控件满足可访问性要求（原生元素、`aria-label`、≥44×44px、`announce()` 播报）。
12. ✅ 浏览器控制台无 error / warning。

**核心逻辑**

1. `exportData()`：先 `ensureModules()` 补齐预设模块，再 `JSON.stringify(state, null, 2)` → `Blob` →
   `URL.createObjectURL` → `<a download="dotledger-backup-YYYY-MM-DD.json">`。导出的是**整个 `state`**，
   含全部历史与未来日期，也含 `modules`。1s 后 `revokeObjectURL`（等下载启动）。
2. `validateBackup()`：fail-fast，返回 `null` 或一句拒绝原因（直接进 `announce`）。除 R1–R17 外，
   额外拒绝空 `days` 等结构性错误；`modules` 缺省视为合法（兼容 TASK-003 之前的备份）。
3. `normalizeBackup()`：重建新对象，未知字段全部丢弃；`mod` 缺省补 `other`；`link` 用与手工录入
   同一个 `safeLink()` 复检，非法协议只丢链接。
4. `importBackup()`：`file.text()` → `JSON.parse`（`try...catch`）→ 校验 → `confirm` 明确「整体替换、
   不可撤销」→ `localStorage.setItem`（`try...catch`）**成功后**才赋 `state` → `selected` 重置今天、
   `activeMod` 重置「全部」→ 四个渲染 + `announce`。
5. 文件选择框 `change` 后立刻 `input.value = ''`，同一文件可重复导入。

**关键决策**

- **`file.text()` 而非 `FileReader`**：原生 API、无事件回调，`await` 后顺序执行，异常路径只有一条。
- **`link` 的宽松度刻意与手工录入一致**：校验阶段只查类型与长度，协议判定交给 `safeLink()`，
  避免「同一份数据，手输能进、导入被拒」的不一致。
- **`modules` 可选**：老备份没有模块表，导入后补预设三家 + 任务归「其他」，不比手工升级更差。
- **触控区用「padding + 负 margin」**：页脚是 13px 小字链接，直接撑高会破坏视觉节奏；
  这条路让可点区域到 44px 而版式不变。取 `--sp-3`（12px）而非 `--sp-4`（16px），
  是为了窄屏换行时触控区刚好不侵入上一行说明文字（实测三档断点无重叠）。
